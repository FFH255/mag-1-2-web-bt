## 4. Требования к программе или программному изделию

### 4.1. Требования к функциональным характеристикам

Программный продукт должен обеспечивать следующие функции:

#### 4.1.1. Режим теста

- Выбор языка набора из предустановленного списка (белорусский, китайский упрощённый, английский, французский, немецкий, греческий, итальянский, японский [хирагана, катакана, ромадзи], русский, испанский) с несколькими вариантами словаря по частотности (1k, 5k, 10k, 25k слов и базовый).
- Выбор раскладки клавиатуры: QWERTY, Dvorak, Colemak, AZERTY, QWERTZ, ЙЦУКЕН.
- Подрежим «слова»: набор заданного количества слов.
- Подрежим «время»: набор текста на протяжении заданного промежутка времени.
- Подрежим «цитата»: набор цитаты на выбранном языке.
- Включение и выключение пунктуации.
- Отображение метрик по завершении теста: скорость (WPM — слов в минуту, CPM — символов в минуту), точность (%), продолжительность.
- Сравнение результата с личным рекордом.
- Сохранение результата для авторизованных пользователей.
- Режим тренировки слов, допущенных с ошибками.
- Создание и сохранение скриншота экрана результата.

#### 4.1.2. Режим уроков

- Выбор раскладки клавиатуры из шести вариантов.
- Структурированная последовательность уроков, разбитых на шаги.
- Отображение результата после каждого шага: WPM, CPM, точность.
- Проверка соответствия результата минимальным порогам: точность не менее 70 %, скорость не менее 130 CPM.
- Сохранение прогресса (пройденных шагов) для авторизованных пользователей.
- Возможность продолжить незавершённый шаг или начать шаг заново.
- Очистка истории прогресса по выбранной раскладке.

#### 4.1.3. Режим практики

- Адаптивный алгоритм генерации слов из подмножества алфавита, соответствующего текущему уровню пользователя.
- Постепенное открытие новых клавиш по мере улучшения показателей по всем текущим открытым клавишам.
- Условие открытия новой клавиши: не менее 5 завершённых сессий по каждой открытой клавише, все клавиши — с точностью 100 %.
- Выделение «целевой клавиши» — наиболее проблемной по результатам, которая включается в каждое сгенерированное слово.
- Панель клавиш с отображением статуса (открыта/закрыта) и производительности.
- Настройки режима: язык практики, раскладка, тип отображения скорости (WPM/CPM/CPS), целевая скорость.
- Дневная цель: по суммарному времени (минуты) или по количеству завершённых сессий.
- Уведомление о достижении дневной цели.
- Уведомление об открытии всех клавиш языка.
- Онбординг-руководство при первом запуске режима.

#### 4.1.4. Авторизация и управление учётной записью

- Регистрация и вход через OAuth2-провайдеры: Google, GitHub.
- Выбор уникального имени пользователя (никнейма) при первой регистрации.
- Управление сессиями с поддержкой обновления JWT-токена.
- Выход из учётной записи.

#### 4.1.5. Профиль пользователя

- Отображение публичного профиля пользователя по никнейму.
- Статистика: среднее WPM, среднее CPM, средняя точность, количество начатых тестов, количество завершённых тестов, суммарное время печати.
- Личный рекорд в режиме «слова» и режиме «время».
- Дата регистрации.
- Позиция пользователя в глобальной таблице лидеров.

#### 4.1.6. Таблица лидеров

- Отображение глобальной таблицы лидеров с ранжированием пользователей.
- Отображение персональной позиции авторизованного пользователя.

#### 4.1.7. Настройки интерфейса

Пользователь должен иметь возможность настраивать:

- раскладку клавиатуры (для отображения);
- внешний вид курсора;
- инвертирование цветов символов;
- скорость анимации курсора;
- отображение виртуальной клавиатуры;
- отображение рук на клавиатуре;
- режим завершения теста (на последней букве или после пробела);
- размер шрифта в тестовом блоке;
- режим отображения слов (rows — несколько строк; tape — единая полоса);
- отступ в tape-режиме;
- режим фокуса (скрытие вспомогательных элементов интерфейса);
- режим «нет пути назад» (запрет удаления введённых символов);
- скрытие лишних (extra) букв.

#### 4.1.8. Цветовые темы

- Выбор цветовой темы интерфейса. Тема по умолчанию: `native_dark`.

#### 4.1.9. Многоязычность интерфейса

- Интерфейс должен поддерживать три языка: английский (по умолчанию), русский, французский.

#### 4.1.10. Управление cookies

- Информирование пользователя о применяемых cookies при первом посещении.
- Разделение cookies на категории: необходимые (essential), аналитические (analytics), маркетинговые/рекламные (marketing and ads).
- Возможность пользователя выбрать категории разрешённых cookies.

### 4.2. Требования к надёжности

- Идемпотентность сохранения результатов тестов: повторная отправка идентичного запроса не должна создавать дублирующей записи (реализуется посредством ключа идемпотентности).
- Периодическая очистка истёкших пользовательских сессий: интервал — каждые 24 часа.
- Защита от подделки результатов (антифрод): применение системы ротируемых ключей с интервалом ротации 6 часов; максимальное количество одновременно действующих ключей — 5.
- Ограничение частоты запросов к API (rate limiting).
- Кэширование профилей пользователей с TTL 10 минут; кэширование личных рекордов с TTL 15 минут.
- Хранение заблокированных JWT-токенов для исключения их повторного использования.

## 2. Функциональное назначение

«Blind Typing» — онлайн-тренажёр для обучения методу слепой печати (touch typing). Программный продукт предоставляет пользователю три режима работы:

1. **Тест** — разовая проверка скорости и точности набора текста.
2. **Уроки** — структурированный курс для последовательного освоения клавиатурной раскладки.
3. **Практика** — непрерывное обучение на основе адаптивного алгоритма, подстраивающегося под индивидуальные показатели пользователя.

Дополнительные функции: регистрация и хранение статистики, глобальная таблица лидеров, публичный профиль пользователя, настройки отображения и поведения тренажёра.

Программный продукт поддерживает набор текста на 10 естественных языках (включая кириллические и иероглифические) и 6 клавиатурных раскладках. Интерфейс доступен на трёх языках: английском, русском, французском.

## 3. Описание логической структуры

Программный продукт построен по многоуровневой клиент-серверной архитектуре и состоит из следующих компонентов:

### 3.1. Клиентская часть (Frontend)

Реализована на основе Next.js 16 с серверным рендерингом (SSR). Взаимодействует с серверной частью посредством REST API (HTTP/JSON).

**Структура слоёв (по методологии Feature-Sliced Design):**

| Слой | Назначение |
|---|---|
| `app` | Маршруты Next.js App Router, конфигурация интернационализации |
| `screens` | Страничные компоненты (test, lessons, practice, me, user, preferences и др.) |
| `widgets` | Составные UI-блоки |
| `features` | Изолированные функциональные модули |
| `entities` | Доменные сущности |
| `shared` | Утилиты, константы, базовые UI-компоненты |

**Управление состоянием:** MobX 6 (глобальное состояние), TanStack Query 5 (серверное состояние и кэш запросов).

**Маршруты приложения:**

| Маршрут | Раздел |
|---|---|
| `/[locale]/` | Главная страница (Landing) |
| `/[locale]/test` | Режим теста |
| `/[locale]/lessons` | Режим уроков |
| `/[locale]/lessons/[keymap]/[...parameters]` | Прохождение шага урока |
| `/[locale]/practice` | Режим практики |
| `/[locale]/me` | Профиль текущего пользователя |
| `/[locale]/me/statistics` | Статистика текущего пользователя |
| `/[locale]/me/settings` | Настройки учётной записи |
| `/[locale]/user/[username]` | Публичный профиль пользователя |
| `/[locale]/preferences` | Настройки интерфейса |
| `/[locale]/auth` | Обработка OAuth2-колбэков |

### 3.2. Серверная часть (Backend)

Реализована на Go 1.24 с HTTP-фреймворком Gin 1.10. Обрабатывает REST API-запросы, содержит бизнес-логику и взаимодействует с базами данных.

**Слои backend:**

| Слой | Путь | Роль |
|---|---|---|
| API | `src/internal/api/` | Gin-обработчики, middleware, cookie-хелперы |
| Services | `src/internal/services/` | Бизнес-логика |
| Repositories | `src/internal/repositories/` | Доступ к PostgreSQL и Redis |
| Models | `src/internal/models/` | Доменные типы с валидацией |
| Scheduler | `src/internal/scheduler/` | Фоновые cron-задачи |
| DI Container | `src/internal/app/di/` | Инициализация зависимостей |
| Config | `src/internal/app/config/` | Структуры конфигурации из YAML-файлов |

**REST API (основные эндпоинты):**

| Метод | Путь | Описание |
|---|---|---|
| GET | `/auth/{provider}` | Инициация OAuth2 |
| POST | `/auth/{provider}/callback` | Колбэк OAuth2 |
| POST | `/auth/register` | Завершение регистрации |
| POST | `/auth/refresh` | Обновление JWT-токена |
| POST | `/auth/logout` | Выход из системы |
| GET | `/users/me` | Профиль текущего пользователя |
| POST | `/users/me/statistics` | Сохранение результата теста |
| GET | `/users/me/statistics` | Статистика текущего пользователя |
| DELETE | `/users/me/statistics` | Удаление статистики |
| PATCH | `/users/me/username` | Смена никнейма |
| GET | `/users/me/leaderboard-positions` | Позиции в таблице лидеров |
| GET | `/users/me/lesson-progress` | Прогресс уроков |
| POST | `/users/me/lesson-progress` | Сохранение прогресса урока |
| GET | `/users/{username}/profile` | Публичный профиль |
| GET | `/users/username-availability` | Проверка доступности никнейма |
| GET | `/leaderboard` | Таблица лидеров |
| GET | `/antifroad/key` | Получение антифрод-ключа |

**Антифрод-система:** ключи хранятся в таблице `antifroad_keys`, ротируются каждые 6 часов; максимум 5 одновременно действующих ключей. Ключ включается в каждый запрос сохранения результата теста.

**Фоновые задачи (Scheduler):**

| Задача | Интервал |
|---|---|
| Удаление истёкших сессий | каждые 24 часа |
| Ротация антифрод-ключей | каждые 6 часов |

### 3.3. Схема базы данных (PostgreSQL)

**Таблица `users`:**

| Поле | Тип | Описание |
|---|---|---|
| id | SERIAL | Первичный ключ |
| email | VARCHAR(128) | Электронная почта (уникальная) |
| nickname | VARCHAR(32) | Имя пользователя (уникальное) |
| provider | VARCHAR(32) | OAuth2-провайдер (google / github) |
| created_at | TIMESTAMPTZ | Дата регистрации |

**Таблица `sessions`:** хранит активные пользовательские сессии.

**Таблица `statistics`:**

| Поле | Тип | Описание |
|---|---|---|
| id | SERIAL | Первичный ключ |
| user_id | INTEGER | Внешний ключ → users |
| wpm | DOUBLE PRECISION | Скорость (слов/мин) |
| cpm | DOUBLE PRECISION | Скорость (символов/мин) |
| accuracy | DOUBLE PRECISION | Точность (%) |
| duration | BIGINT | Продолжительность теста |

**Таблица `lesson_step_results`:**

| Поле | Тип | Описание |

**Таблица `antifroad_keys`:** хранит текущие антифрод-ключи.

### 3.4. Redis

Redis используется для:
- Таблицы лидеров (sorted sets).
- Кэша профилей пользователей (TTL 10 минут).
- Кэша личных рекордов (TTL 15 минут).

## 5. Вызов и загрузка

### 5.1. Клиентская часть

Доступ к программному продукту осуществляется через адресную строку веб-браузера: https://blindtyping.com. Установка дополнительного программного обеспечения не требуется.

### 5.2. Серверная часть

Запуск серверной части производится командами из директории `backend/`:

| Команда | Среда |
|---|---|
| `make local` | Локальная разработка (`docker-compose.local.yaml`) |
| `make debug` | Отладка с полным сбросом состояния (`docker-compose.debug.yaml`) |
| `make prod` | Продуктивная среда (`docker-compose.prod.yaml`) |

Порядок инициализации при запуске: загрузка YAML-конфигурации → инициализация DI-контейнера → PostgreSQL + применение миграций → Redis → Scheduler → антифрод-сервис → HTTP-сервер.

HTTP-сервер прослушивает порт `5005`.

## 6. Входные данные

| Источник | Данные |
|---|---|
| Клавиатура пользователя | Нажатия клавиш в ходе теста, урока или практики |
| Интерфейс (выбор параметров) | Язык набора, раскладка клавиатуры, режим теста (слова/время/цитата), количество слов, продолжительность, включение пунктуации, цветовая тема, настройки интерфейса (preferences) |
| OAuth2-провайдер | Данные авторизации (email, провайдер) от Google или GitHub |
| Форма регистрации | Имя пользователя (никнейм) |
| Форма настроек практики | Язык практики, раскладка, целевая скорость, тип дневной цели, значение дневной цели |

## 7. Выходные данные

| Выходные данные | Формат / хранилище |
|---|---|
| Результат теста: WPM, CPM, точность, продолжительность | Экран результатов; запись в таблице `statistics` (PostgreSQL) |
| Прогресс урока: WPM, CPM, точность, продолжительность по шагу | Экран результатов урока; запись в таблице `lesson_step_results` (PostgreSQL) |
| Профиль пользователя: сводная статистика, личные рекорды | Страница профиля; кэш Redis |
| Таблица лидеров | Страница лидеров; sorted set Redis |
| Позиция пользователя в таблице лидеров | Страница профиля / личного кабинета |
| Прогресс режима практики: открытые клавиши, показатели по клавишам, дневная цель | Экран режима практики; локальное хранилище браузера (IndexedDB / localStorage) |
| Скриншот результата теста | Изображение, загружаемое пользователем |
| Swagger-документация API | `/swagger/` на сервере |
